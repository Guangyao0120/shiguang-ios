# 拾光 · iPhone 本地相册整理

当前 0.8.2/build11。SwiftUI、PhotoKit、Vision、Core ML、ActivityKit、Speech；最低 iOS17。直接引用已授权的苹果照片。本地识别和搜索不调用付费 API；DeepSeek 在发送前预览确认。

## 0.8.2 修复与调整

- 主分类、全部人像、具体人物、出游统一进入同一连续整理界面；照片和视频均保持「查看清晰 / 下一张 / 放入待删」的顺序，支持左下一张、右上一张、上滑待删、撤销。修正首次清晰预览的呈现方式。
- 暂停立即接管当前批次，提交已完成结果，不等待尚未返回的单张识别；旧任务的迟到回调不再影响继续整理。
- 整理过程中每24项或约2秒检查并提交已完成记录，暂停/结束立即保存。继续时从现有分析进度起步，只处理剩余候选。
- Vision请求支持取消及超时；连续读取/识别错误会停止当前扫描并保留已完成记录。临时读取失败留作重试。
- 读取数据库出错时显示恢复入口，不把错误当空库覆盖。保存失败保留内存并显示重试保存。目录不完整时保留旧分析，仅成功的系统删除会移除缓存记录。
- 待删区支持选择、全选、恢复所选、删除所选。扫描中可以发起删除，先暂停保存再交给系统确认；只清除系统确认删除成功的可删除照片，取消和失败保留队列。

模拟器检查及真机验证状态见 VALIDATION.md；系统终止前尚未落盘的少量结果仍可能需要重新识别，后台执行仍由iOS安排。

## 0.8.1 修复与调整

- 图标改为背景铺满的正方形画稿，去掉黑色四角和预制圆角外框，保留彩色玻璃花瓣，由iOS施加圆角。
- 主页各分类、人物、出游的连续整理使用同一固定照片队列；待删改变栏目列表时不再重排当前队列，修复跳张/返回错位。左滑下一张、右滑上一张、上滑待删，默认2048清晰图；查看原图后保留位置，只有新标待删时前进。
- 收据、发票、支付记录、票券统一投影到「票据」。保留旧枚举解码和已有手动修正。
- 风景拆为「城市风光」「自然风光」；一张照片可同时归入两类。已有视觉线索直接分类，旧风景缺少线索时优先补图像分类，不重复OCR；不确定的归待确认。
- 读取下一张与识别当前图片重叠进行，最多提前读取一张。复用串行Vision请求，截图合并执行人脸/分类/准确文字识别，保留原识别分辨率、语言与精度。
- 整理记录迁移到SQLite WAL，正常保存只写变化记录，事务统一提交；旧JSON保留作迁移备份。语义相同的快照，包括重开App后，不重复写入。一次迁移后不能用旧版JSON查看后续最新进度。
- 保存无图片、无OCR内容的匿名阶段耗时，用于分辨读取等待和Vision计算的瓶颈；每10秒或暂停/结束更新，数据保存在本机。
- Sideloadly会修改应用标识，本次安装包已按实际签名后标识调整后台任务配置，保留具体任务项及通配许可。源码的通用标识仍适合正常Xcode构建；侧载到其他账号时需同步调整。

实际速度、发热、后台批准时长和灵动岛交互仍需用户真机使用比对。5.4张/秒是一万张约31分钟，不是每批只允许5张；本轮不承诺具体提速倍数。

## 0.8 原有功能

- Apple Vision 已用于本地图片分类、人脸框、截图文字识别；增加美食分类并保存视觉标签。
- CLIP ViT-B/32 转为 Core ML FP16，图像和文字两个模型直接随 App 安装。模型来自 MIT 许可的 OpenAI CLIP 固定提交，保留许可证；使用 CPU/Neural Engine，不要求 GPU 后台资源。
- 「用描述找照片」建立独立 SQLite 特征索引，Float16 特征每张约1KB。增量识别新增或修改的图片；权限隐藏、已移除、待删和内容变化的旧特征不参与当前搜索。不将特征放入启动用的整库 JSON。
- 搜索先读取已建索引的照片，显示覆盖数量和相关候选。常见法棍/美食词在本机处理，其余中文及非英文描述通过 iOS18+ 系统本地翻译转为英文；初次可能需要下载系统语言包。不会自动回退到付费 API。
- 去掉每张100ms固定等待。Vision由每5张刷新整库改成最多24张或约2秒提交；界面反馈约半秒更新，系统进度约1秒更新。搜索索引16张一个持久化事务。显示实际处理张/秒。
- 相册目录、文字识别、搜索索引分开。进入 App 读取已保存分类，不自动启动整库 Vision/CLIP 推理。
- CLIP索引和Vision整理都支持用户发起的iOS26持续后台任务，并保存进度供系统分批续跑。主动暂停会记住；没有无限后台承诺。
- 灵动岛/锁屏整理进度：持续后台任务采用系统卡片；未接入系统卡片时使用ActivityKit扩展，点击回到App，暂停链接打开App并停止整理，避免同时显示两张进度卡。
- 连续整理：左滑下一张，右滑上一张，上滑待删；直接请求2048尺寸清晰图，并可打开系统原图预览缩放。iCloud原件下载由用户发起。
- 首次引导先问整理范围，提前申请照片权限，在后续问题期间读取目录；升级保留现有授权与整理记录。
- 设置支持跟随系统、简体中文、英语、日语、韩语、西班牙语、俄语；主要栏目、操作、设置和引导已翻译。用户命名、OCR和原始标签存储保留。
- 使用用户下载目录提供的玻璃花瓣相册图标。

已有功能包括：重叠分类、自定义内容标签和分类、人物/行程关联、离线节日和城市行程候选、相似照片候选、待删集中审核、用户确认后创建系统相册、本机逐个视频转写与可编辑祝福标题、DeepSeek可选识别和指令解析。

## 构建

GitHub Actions 使用 Xcode26.3/iOS26.2 SDK，自动准备模型、运行测试并生成真机IPA和诊断符号。源码包不重复包含约304MB的编译模型；本地Mac首次构建前需要Python3.11安装 `scripts/prepare_clip.py` 顶部列出的固定依赖并运行该脚本，然后用Xcode打开工程。模型准备完成后，App运行和搜索不需要模型下载服务。

真机IPA为未签名产物，需使用自己的开发者账号签名。此次已沿用原账号和应用标识覆盖安装。商店发布还需要正式会员、签名、隐私资料和审核，见[使用与发布.md](使用与发布.md)。证据与实测边界见[VALIDATION.md](VALIDATION.md)。

## 实际边界

首次建立索引需要逐张读取和推理，会耗电和占用存储。CLIP相似度不是识别概率；切片、遮挡、小物体或相似食品可能漏检/误检，结果按候选展示。尚未用用户图库验证法棍检索准确率、手机吞吐、冷启动时长、帧率或温度改善。

画面搜索当前覆盖静态照片；视频暂不参与CLIP整段搜索。视频语音仍逐个发起、本机普通话/英语、最长10分钟，不承诺后台转写或完整视觉理解。人物身份由用户关联；相似候选不是文件级精确查重。行程地点仅限内置城市中心范围。主要界面已本地化，部分旧功能的长说明和识别依据仍为中文。

后台许可、执行时长、灵动岛可见性与通知送达由iOS及用户系统设置决定，需真机使用确认。DeepSeek真实账户尚未联调。原图在苹果照片；分类、待删、转写和搜索特征保存在本机App目录。覆盖安装保留数据，卸载会清空私有整理记录。无独立导出恢复功能。
